📁 raw/yellow_tripdata_2016-03.csv
   Source: NYC Taxi & Limousine Commission
   URL: https://data.cityofnewyork.us/Transportation/2016-Yellow-Taxi-Trip-Data/k67s-dv2t
   Size: 1,988,474,675 bytes (1.9 GB)
   Rows: 12,210,952
   Columns: 19 (we use 9, ignore 10)
   Period: 1-31 March 2016
   Status: ✅ INCLUDED (if present) / ⚠️  DOWNLOAD REQUIRED (if absent)
   
   Used columns:
     • tpep_pickup_datetime, tpep_dropoff_datetime
     • pickup_longitude, pickup_latitude, dropoff_longitude, dropoff_latitude
     • trip_distance, fare_amount, tip_amount

   Ignored columns:
     • VendorID, passenger_count, RatecodeID, store_and_fwd_flag
     • payment_type, extra, mta_tax, tolls_amount, improvement_surcharge

   Known anomalies:
     • 71,126 rows with zero distance
     • 182,001 rows with (0,0) coordinates
     • 21 rows with distance > 1,000 miles
     • 4,581 rows with negative fare
     • 12,550 rows with dropoff at or before pickup

📁 processed/distance.npz
   Shape: 87 × 87
   Size: ~53 KB
   Purpose: Geo(a,b) distance matrix (km)
   Method: Median observed distance + rotated-L1 fallback
   Validation: Circuity 1.320 (matches known NYC value ≈1.3)
   Rebuild: python -m ltf.data.graph
   Status: ✅ INCLUDED

📁 processed/traveltime.npz
   Shape: 87 × 87 × 48
   Size: ~1.6 MB
   Purpose: Time-dependent travel time (GAP 1a correction)
   Profiles: 48 = 2 day types × 24 hours
   Estimation: 13.5% L0 (direct), 60.3% L1 (scaled), 26.2% L2 (fallback)
   Key finding: Peak/off-peak spread median 2.11×, max 4.35×
   Rebuild: python -m ltf.data.traveltime
   Status: ✅ INCLUDED

   Why separate: Prevents temporal leakage - forecaster cannot see future
   Rebuild: python -m ltf.data.traveltime
   Status: ✅ INCLUDED

📁 processed/traveltime_test.npz

📁 processed/demand.npz

  DATA FLOW AND DEPENDENCIES
═══════════════════════════════════════════════════════════════════════════════

yellow_tripdata_2016-03.csv (raw)
        │
        ├─ pass 1: count grid-cell volume ──→ nodes.csv
        │
        └─ pass 2: filter + snap to nodes ──→ trips.parquet
                │
                ├─→ distance.npz (median observed distance)
                │
                ├─→ traveltime.npz (full month - environment physics)
                │   traveltime_train.npz (pre-test-week - forecaster)
                │   traveltime_test.npz (test week - evaluation)
                │
                └─→ demand.npz (request counts per OD pair per hour)

All arrows represent deterministic transformations.
Given the raw CSV, the entire processed/ folder rebuilds in ≈2 minutes.

  REBUILD INSTRUCTIONS

Given raw/yellow_tripdata_2016-03.csv, rebuild everything:

  python -m ltf.data.prepare      # → nodes.csv, trips.parquet
  python -m ltf.data.graph        # → distance.npz
  python -m ltf.data.traveltime   # → traveltime*.npz (3 files)
  python -m ltf.data.demand       # → demand.npz

  python -m scripts.verify_phase1

  # Regenerate documentation

  python -m scripts.make_dataset_docx   # → MTP_Dataset_Report.docx
